# AssetOps

Учебный веб-проект на основе ВКР: учёт вычислительной техники, обработка сервисных заявок и аналитика обслуживания.

## Возможности

- Панель состояния оборудования и заявок.
- Реестр техники с фильтрами и карточками оборудования.
- Журнал заявок, история обработки и назначение исполнителей.
- Аналитика, уведомления и настройки правил обслуживания.
- Демонстрация интерфейсов администратора, диспетчера, инженера и наблюдателя.
- Локальный анализ заявок: категория, рекомендуемый приоритет, риски и следующие действия.

## Стек

**Python · SQLite · JavaScript · HTML · CSS**

Сервер использует стандартную библиотеку Python. Установка сторонних Python-пакетов и ключи внешних API не требуются.

## Демонстрационные данные

Текущий набор сгенерирован для портфолио: 8 вымышленных устройств и 8 заявок, пользователи и отделы с префиксом «Демо».

## Быстрый запуск

Нужен Python 3.10 или новее. Откройте терминал в папке проекта:

```bash
python3 database/init_db.py
python3 server.py
```

Откройте http://127.0.0.1:8000. На Windows вместо `python3` можно использовать `py`.

На странице `login.html` выберите демонстрационную роль и нажмите кнопку входа. Это имитация входа: пароль не проверяется.

Инициализация базы загружает начальный набор данных. Повторный запуск скрипта пересоздаёт таблицы; используйте его для сброса демонстрационной базы.

## Архитектура

Браузер загружает HTML/CSS/JavaScript и начальные данные из Python API. Сервер читает SQLite; при недоступном API интерфейс использует `assets/data.js`. Клиентские изменения и настройки сохраняются в `localStorage` браузера.

Модуль `ai_engine.py` использует правила и ключевые слова для анализа заявки. Это эвристический алгоритм, без нейросети и внешнего LLM API.

```text
assetops/
├── *.html               # Страницы интерфейса
├── assets/
│   ├── app.js           # Клиентская логика
│   ├── data.js          # Начальные данные для автономного режима
│   └── styles.css       # Стили
├── server.py            # HTTP-сервер и JSON API
├── ai_engine.py         # Анализ заявок на основе правил
└── database/
    ├── schema.sql       # Структура SQLite
    ├── seed.sql         # Начальный набор данных
    └── init_db.py       # Создание локальной базы
```

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/db/status` | Состояние базы и число записей |
| GET | `/api/data` | Начальные данные интерфейса |
| GET | `/api/ai/status` | Состояние локального анализатора |
| POST | `/api/ai/analyze-ticket` | Анализ заявки |

## Границы прототипа

Проект предназначен для локальной демонстрации и портфолио. Роли реализованы на стороне клиента, серверной аутентификации и разграничения доступа нет. Изменения в браузере не образуют общую многопользовательскую базу. Встроенный HTTP-сервер не предназначен для эксплуатации в интернете.

В репозиторий включены исходники приложения и начальные SQL-данные. Локальная база создаётся при запуске; текст ВКР, презентации и рабочие документы не входят в проект.
